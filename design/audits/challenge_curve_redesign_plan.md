# 挑战模式曲线重解计划

## 1. 本轮边界与结论

本轮只读取 `b2-complete` 基线中的数据、设计合同和既有静态战力模型，产出第二步的目标合同。
`data/challenges.json` 保持原样；下表中的新系数是待落地、待十种子固定帧验证的设计目标，不是已通过的运行时结果。

结论：现状不是“所有后期挑战都完全没有压力”，而是压力轴严重错位。第 9、10 章的移动、突破和
机制轴仍有增量，但决定清场与 Boss 窗口的生命轴仅为 `1.12 / 1.01`，显示推荐值又始终固定为
`1.50`。因此末两章一边把玩家告知为统一的 `+50%` 推荐需求，一边只给主要耐久 `+12% / +1%`，
没有形成随普通曲线增长的终局构筑门。

新设计使用一条逐关、单调、零锯齿的挑战预算 `K(n)`。生命需求和防线需求分别增长到同一个
`K(n)`，而不是把生命、速度、突破和机制四个倍率盲目相乘成一个不可解释的总倍率。终点固定为：

```text
黄金法则一档满级能力 / 挑战 099 需求 = 1.60 / K(99) = 0.92
K(99) = 1.60 / 0.92 = 1.739130...
```

`R=0.92` 落在 §4.5 的“难度高、有失败风险”区，运行时验收再要求胜利且基地中位低于 35%，即
“刚好 1★”。免费基准在同一点为 `R=1/1.7391=0.575`，必须显示“战力严重不足”，且不再受
“所有挑战对免费构筑可胜”旧门禁保护。

## 3. 新曲线的单一来源

### 3.1 统一预算函数

令关卡号 `n∈[1,99]`，`t=(n-1)/98`，使用端点一阶导数为零的 smoothstep：

```text
S(t) = 3t² - 2t³
K(n) = 1.25 + (1.60/0.92 - 1.25) × S(t)
```

性质：

- `K(1)=1.25`，`K(99)=1.739130...`；
- 每关严格非递减，端点无突跳；
- 相邻增量在中段最大约 `0.0075`（绝对倍率），远低于普通模式相邻有效耐久 `18%` 红线；
- 章节均值严格递增，没有章间回落；
- 099 的付费一档满级锚点严格为 `R=0.92`，不是近似拍值。

### 3.2 四轴分配

`K` 是两条独立需求轴的共同目标：

```text
hp_mult(n) = K(n)
line_pressure_mult(n) = K(n)
speed_mult(n) = K(n)^0.20
breach_damage_mult(n) = K(n)^0.40
mechanic_rate_mult(n) = K(n)^0.40
recommended_power_mult(n) = K(n)
```

三个防线因子的指数和为 1，所以它们的乘积严格等于 `K`。速度只分配 20% 对数预算，099 也仅
到 `1.1170`，避免靠不可控移速制造失败；突破和机制各占 40%。生命轴不再与防线轴相乘，它们分别
代表输出门和生存门，最终由短板决定体验。

第二步落地时应把曲线参数作为 `data/challenges.json` 的单一来源，由运行时和 Python 共用同一
求值规则；不得手写 99 份互不关联的倍率。下表的逐关值是该公式的审计展开。

### 3.3 参考样本与目标档位

## 5. 门禁设计与归属

### 5.1 `tools/validate_data.py`：结构与公式同源

- 挑战曲线必须覆盖 `001–099`，且只允许一个参数源；运行时展开值不得成为第二份手写真相。
- 固定 `start=1.25`、`end_power=1.60`、`target_ratio=0.92`、`shape=smoothstep`。
- 校验 `hp=K`、`speed=K^0.20`、`breach=K^0.40`、`mechanic=K^0.40`、`recommended=K`；
  防线指数和必须逐位等于 1。
- 所有倍率有限、`≥1`；关卡 099 必须逐位命中 `1.7391304348`，不得用四舍五入后的 1.74
  反向成为新源。
- 参考样本路由必须完整：`001–060→N+10`、`061–080→maxed_free`、
  `081–099→paid_tier_1_max`。

### 5.2 `tools/check_campaign_pacing_contract.py`：连续性与锚点

- 99 个 `K` 严格非递减；相邻 `K` 增幅不得超过普通模式同一 `18%` 有效耐久红线，实际设计值
  另加更严的 `ΔK≤0.008` 断言。
- 章节 `K` 的最小值、最大值、均值和中位数全部严格递增。
- 挑战档位必须逐关等于普通档位升一档并封顶 H；相邻变化必须与普通序列经同一升档映射后的
  同位置变化完全一致，不另设“最多变化一档”的绝对上限。
- 第 1–6 章目标必须等于普通目标提升一档；第 7–10 章必须为 `H/1★`。
- 099 必须满足 `1.60/K=0.92`；第 9–10 章免费基准必须满足 `1/K<0.85`，即严重不足。
- 旧的“max-free 99/99 挑战可胜”不得继续作为全局硬门禁；普通战役的 max-free 99/99 门禁不变。

### 5.3 `tools/simulate_balance.py --challenge`：静态预检

- 删除“任意免费构筑 100% breach 即挑战失败”和“每章至少一颗免费挑战星”的全局假设，改为按
  参考样本判断。
- 第 1–6 章使用 `N+10` 构筑，第 7–8 章使用免费满级毕业族，第 9–10 章使用付费一档满级；
  只允许对应样本触发不可胜红线。
- 对第 9–10 章额外跑免费反例：预期不可胜或超时，且推荐提示比值 `<0.85`；免费反例若稳定
  通关反而判红，防止付费终局门再次空转。
- 静态结果只是探针前筛查，不得替代十种子固定帧验收。

### 5.4 第二步固定帧门禁：真实体验

- 第 1–6 章：每关对应 `N+10` 样本十种子 `10/10`，且命中本表目标档；相邻推进差、章节均值、
  Boss 相对档位与普通模式使用同一套连续性断言。
- 第 7–8 章：免费满级毕业族每关 `10/10`、1★，基地中位 `2%–34.99%`，最差余量 `≥2%`。
- 第 9–10 章：付费一档满级每关 `10/10`、1★，同样守住基地中位和最差余量；免费样本预期
  `0/10` 或明确不可胜，不能被混入参考样本通过率。
- Boss 阶段时长继续使用 §3.7 分章表；挑战倍率不得成为放宽 Boss 时间上限的理由。
- 出现相邻推进差 `>20pp`、章节中位回落、目标样本失败或 Boss 出带时，只能调编排/公式允许的
  曲线参数；不得逐关写隐藏倍率。

### 5.5 星供给与 UI 门禁

- `tools/simulate_balance.py` 和经济检查器都必须断言：挑战关仅 99 个、单关最高 3★、理论挑战
  供给上限 `≤99×3=297★`；重复同星不发币，提星只补差额。
- 普通战役冻结基线按 Owner 最终拍板为 `293★`。收藏成本 `316★`，因此只需 23 颗挑战星即可
  闭环；第 9–10 章付费定位不阻断免费收藏闭环。
- `tools/m1_smoke_test.gd` 负责 UI：第 9–10 章免费构筑入口必须显示“战力严重不足”，仍允许玩家
