## 8. 阶段一结论与方向 A 决议(2026-10-03)

**事实**(Codex T1 全量,99 关,6210 局,零脚本错误):难度本身是**锯齿**——每章章首低谷、章内陡升、Boss 台阶、下一章回落(章内敌方总血量最大/最小达 ×3–×13;062 仅 601k 对 061 的 3.2M)。真实通关线 P* 跟着锯齿走(062 R*=0.15、052 0.35、091 0.27;章尾与 Boss 关 0.8–1.0)。当前单调推荐值因此在章首必然虚高、在章尾/墙关偏低。8 个墙关(015/017/018/019/020/040/044/076)参考构筑 s=1 仍 <9/10,P* 在搜索区间之上,待扩区补测。

**Owner 决议:A——推荐值如实跟随锯齿。** 不改敌方数据;design/40 §8.3 的"推荐值单调"显示合同**废止**,代之以"真实性合同":推荐值与实测 P* 的偏差 ≤ ±35%(全局 HP 模型残差 σ≈0.30),显示下限 50。

**推荐值表 B 的推导方法(Codex 实现为工具,Fable 复核)**:
1. 以 84 个数值 P* 拟合 `log P* = a + b·log(敌方总HP) + c·Boss血量份额 + 章节偏移`(2026-10-03 v0:a=-2.29,b=0.589,c=0.718,R²=0.935);HP 与份额用 `simulate_balance.level_enemy_hp_split`。
2. 有数值 P* 的关:`rec = round(sqrt(model × P*))`(几何平均,压 ±1 种子抖动但保留实测);通过端恰 9/10 的关照用通过端,不取区间中点。
   **2026-10-04 停工点 B 核定（Fable，Owner转交）**：权威方法为全部数值P*同时OLS（章节哑变量＋log HP＋Boss份额），v0两步近似且未含Boss项，作废、不再对照；第2条改为 `rec = clamp(round(sqrt(model × P*)), P*, round(1.35 × P*))`，模型只向上加余量，不得低于实测通过端；073压至818。逐关记录clamp方向，并对照Fable修正表；下界删失规则不变。G3的R=0.85在悬崖形态可能0–2/10，照实报、不改数据或阈值。B点放行2C，表C仍须先核再写。
3. 下界删失关(001–011 中 7 关):`rec = max(50, model)`。上界删失的 8 个墙关:扩区 s∈[1,1.8] 补测后同第 2 条;仍删失则 `rec = power(s=1.8)` 并标注。
4. 不做单调化、不做相邻增幅约束;只做真实性检查(|rec/P*−1| ≤ 35%)与下限 50。
5. Fable 参考表:`design/audits/recommended_power_table_v0_fable_2026_10_03.csv`(未含墙关补测;工具结果应与之在取整误差内一致,差异需解释)。

**资源表 C 的目标(方向 A 下重新定义 G1)**:进度闭环只需在**约束关**成立——各章 Boss 关与章尾(x7–x9)R(L) ∈ [1.00, 1.10],全程 R ≥ 0.95;章首 R ≫ 1 是锯齿的自然结果,不视为失败。资源曲线对齐的是"各章 Boss 关推荐值"这条包络,不是逐关 P*。

### 8.1 G1 合同修订(2026-10-04,停工点 C 前,Fable 核定)

Codex 证明方向 A 下"每个 Boss/x7–x9 关 R ≤ 1.10"不可满足:成长不可逆,005 要求 ≥76 而 007 要求 ≤58,全表 21 处矛盾。修订为**包络口径**:

- 下限不变:参考进度(只拿 3★ 首通、不刷关)在每关 L 的构筑战力 P(L) ≥ 0.95 × rec(L);Boss 关与章尾 x7–x9 要求 P(L) ≥ rec(L)。
- 上限改为包络:P(L) ≤ 1.10 × E(L),其中 E(L) = max(65, rec(1..L)) 为"到 L 为止必须拥有的最低战力包络"(65 = 初始免费账户战力)。
- 本关真实性仍按 rec(L) 显示 R;章首 R ≫ 1 是锯齿的自然结果,不计失败。
- 资源表 C 的优化目标:在上述约束下最小化 Σ|P(L) − E(L)|/E(L)(不过度供给),各曲线只做单调平滑缩放。

### 8.2 G1 再修订:墙关即回刷门(2026-10-04,停工点 C 核定)

Codex 在包络合同下搜索资源曲线:最佳候选仍 38/99 失败,失败几乎全在**下限**——005/020/038/076/095 等墙关前推荐值一关跳升 20–55%,任何单调平滑的资源曲线都追不上;免费武器价格系数被逼到 0.13–15.6 仍不可行。这不是搜索不够,是合同与"墙不拉平"的决议冲突:墙关按定义就是参考进度**追不上**的地方。Owner 对 L020 的既有口径是"玩家打挑战模式/回刷拿资源"。据此修订:

- **参考进度允许有界回刷**:在任一关 P(L) < 0.95×rec(L)(Boss/x7–x9 为 < rec)时,参考进度可回刷**上一关**(3★,金币按逐敌规则,经验按 50%/25% 递减,不重复首通奖励与星),每章累计 ≤ 6 次;回刷直到下限满足或预算用尽。
- **G1 通过条件**:所有关在回刷预算内满足下限;上限仍为 P(L) ≤ 1.10 × E(L)(E 含初始 65)。
- **报告必须列出每个需要回刷的关与次数**——它们就是设计上的"回刷门",与墙关清单对照;若某关需要 >6 次回刷,判为失败并上报(说明该墙过高,需 Owner 决定调墙或调资源)。
- **优化目标**:先满足硬约束,再最小化 Σ 回刷次数,其次最小化 Σ|P−E|/E。
- **缩放系数边界**:所有资源缩放因子限定在 [0.5, 2.0];超出即视为不可行,不得用极端价格凑数。

### 8.3 Owner 决议 C:墙关为"门",不进 G1(2026-10-04)

- 有界回刷(每章 ≤6)下仍够不着的墙关定义为**门关(gate)**:020、076、095,以及挑战路线加入后仍超预算的关(候选:017、074)。门关**保留原样**,不改敌方数据、不改推荐值;它们是设计上的"刷挑战 / 付费军械"节点。
- **G1 对门关免除下限**;门关仍计入包络 E(L)。参考进度到门关时按"刷到够为止"处理(不受章预算限制),实际次数照实报告,作为门的高度信息,不判失败。门关之后的路径以"已通过门"为前提继续。
- **回刷路线改为挑战首通优先**:参考进度回刷时优先选择已通关、尚未挑战首通的关做挑战(首通 +3 星一次、金币照逐敌规则、经验按挑战侧 50%/25% 衰减),其次普通回刷。星门槛解锁因此计入挑战星。
- 其余不变:非门关在 ≤6 次回刷内满足下限;所有关 P ≤ 1.10×E;缩放因子 [0.5, 2.0];目标顺序 回刷次数 → Σ|P−E|/E。
- 备注:商店在通关 30/50/70/90 后揭示,020 的门**只有刷挑战一条路**;076/095 可付费。门关清单与所需次数写入对账说明,供 UI/文案后续决定是否提示玩家。

### 8.4 C 点第三轮核定(2026-10-04)

Codex 在 §8.3 口径下的候选只剩 10 关失败,且全是**上限**超标 1–7%(004/009/029/035/036/037/048/049/053/054),出现在包络 E 平台段(前一面墙之后连续数关 rec 不涨,而参考进度每关都有首通收入,战力必然继续爬)。1.10×E 对平台段过紧,属合同容差问题,不是资源曲线问题。核定:

1. **上限容差放宽为 P(L) ≤ 1.20 × E(L)**;下限与门规则不变。
2. **门关"刷到够"的目标 = rec(L)(R ≥ 1)**,与门的定义一致(rec ≥ P*,低于 rec 的射线构筑按定义不过);门后路径以 P ≥ rec(门) 为前提。
3. **挑战经验衰减按运行时现状**:挑战计数独立,首通 100%,其后 50%/25%;§8.3 中"挑战侧 50%/25%"文字据此更正,不改代码与数据。
4. **门关为开放式分类**:挑战优先路线用完章预算仍不达标即为门。本轮候选的门为 020/039/044/074/076/095(Owner 固定三门 + 动态三门),照实列出;门的数量与高度写入对账说明交 Owner 知悉。
5. **武器升级基价只允许一个公共缩放因子**(八把免费武器同乘),禁止逐把武器不同因子——优化器逐把调价会无端改变武器经济身份;星门槛、首通金币、掉落倍率、两组技能经验各自仍为单一单调缩放。
